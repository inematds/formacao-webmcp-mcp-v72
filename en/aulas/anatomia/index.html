Lesson 1 · 15 min

Anatomy: tools, resources, and prompts; client, server, and transport

Before you write code, separate the pieces. The MCP server offers three things (tools, resources, and prompts), the client lives inside the app with the model, and the transport is just the pipe. In this lesson you connect a client to the kit's server and see each piece listed.

02 · The three things a server offers

In the kit, a fictional course class service.

1. Tool

A function the model decides to call based on its name, description, and input schema. It can only read, or it can change something in the world.

In the kit: buscar_turmas (read-only) and reservar_vaga (has consequences).

Question that leads the model to call itIs there an MCP class with an open seat?

2. Resource

Read-only data, identified by a URI, that the client lists and attaches as context. The app decides what to read, not the model.

In the kit: turmas://catalogo, the whole catalog in JSON.

3. Prompt

A ready-made request, with arguments, that the client shows for the person to choose (like a slash command or menu item).

In the kit: convite_turma, which builds the request for an invitation to a class.

4. When in doubt

If it changes something or depends on the user's question, it's a tool. If it's stable context the app can attach, it's a resource. If it's a shortcut the person triggers, it's a prompt.

Most services start with just tools, and that's fine.

03 · Revision 2026-07-28: what changed on one screen

The current protocol version is 2026-07-28 (MCP versioning page, read on 10/19/2026). The previous one was 2025-11-25.

What changes the most for anyone coming from 2025: there is no more initialize handshake or session (Mcp-Session-Id); each request carries the version and capabilities in _meta; the client discovers the server with server/discover; and a server that needs to ask the user something returns input_required instead of opening its own request. Roots, Sampling, and Logging were deprecated.

The official SDK that implements this is the v2 line (@modelcontextprotocol/server and @modelcontextprotocol/client, 2.3.1, from 10/05/2026). The old @modelcontextprotocol/sdk package (1.32.1) still speaks 2025-11-25: it's what you'll find in most tutorials.

04 · List the pieces of the kit's server

You need the kit installed (lesson 2, first block). The client talks to the server in the same process, with no port.

Terminal · list
cd ~/projetos/formacao-webmcp-mcp-v72/kit
node listar.mjs; echo "saída: $?"
File · kit/listar.mjs
// listar.mjs — connects an MCP client to the classes server, in the same process (no port),
// and shows the anatomy: protocol era, tools, resources, and prompts.
import { Client, StreamableHTTPClientTransport } from '@modelcontextprotocol/client';
import { createMcpHandler } from '@modelcontextprotocol/server';
import { createServer } from './servidor.mjs';

const handler = createMcpHandler(createServer);
const transporte = new StreamableHTTPClientTransport(new URL('http://teste.local/mcp'), {
  fetch: (url, init) => handler.fetch(new Request(url, init))
});
// mode 'auto': asks server/discover; if the server is old, falls back to initialize.
const cliente = new Client({ name: 'listar', version: '1.0.0' }, { versionNegotiation: { mode: 'auto' } });
await cliente.connect(transporte);

const { tools } = await cliente.listTools();
const { resources } = await cliente.listResources();
const { prompts } = await cliente.listPrompts();
console.log(`era: ${cliente.getProtocolEra()}`);
for (const t of tools) console.log(`ferramenta: ${t.name} · readOnlyHint=${t.annotations?.readOnlyHint}`);
for (const r of resources) console.log(`recurso: ${r.uri}`);
for (const p of prompts) console.log(`prompt: ${p.name}`);
console.log(`${tools.length} ferramentas · ${resources.length} recurso · ${prompts.length} prompt`);

await cliente.close();
await handler.close();
Example from the repository
era: modern
ferramenta: buscar_turmas · readOnlyHint=true
ferramenta: reservar_vaga · readOnlyHint=false
recurso: turmas://catalogo
prompt: convite_turma
2 ferramentas · 1 recurso · 1 prompt
saída: 0

era: modern means the client and server agreed on revision 2026-07-28. With mode: 'legacy' (the v2 client's default) they would fall back to the 2025 initialize.
