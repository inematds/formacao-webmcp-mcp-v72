Lesson 5 · 20 min

Asking the user for input in the middle of the call: MRTR (InputRequiredResult)

Book, pay, delete: an action with consequences needs a yes from a person. In the 2026-07-28 revision, the server no longer opens its own request to ask. It returns input_required, the client asks the user, and repeats the call with the answer. In this lesson you see both rounds and the path of the no.

Start the lesson

In this lesson you will

  1. 1The two rounds: input_required and the call repeated with the answer
  2. 2acceptedContent and inputResponse: reading the yes, the no, and the absence
  3. 3The client must declare that it knows how to ask (elicitation)
  4. 4requestState for multi-step flows, signed

Goal: make the tool with consequences ask for confirmation mid-call with input_required and act only after the yes.

02 · The reservar_vaga handler

Excerpt from kit/servidor.mjs. It is written to run on both rounds: it reads what has already arrived and asks only for what is missing.

Excerpt · reservar_vaga (handler)
async ({ turma_id, email }, ctx) => {
  const turma = TURMAS.find(x => x.id === turma_id);
  if (!turma) return { content: [{ type: 'text', text: `turma ${turma_id} não existe` }], isError: true };
  if (turma.vagas < 1) return { content: [{ type: 'text', text: `turma ${turma_id} sem vagas` }], isError: true };

  const resposta = inputResponse(ctx.mcpReq.inputResponses, 'confirmar');
  if (resposta.kind === 'elicit' && resposta.action !== 'accept') {
    return { content: [{ type: 'text', text: 'reserva cancelada pelo usuário' }], isError: true };
  }
  const ok = acceptedContent(ctx.mcpReq.inputResponses, 'confirmar', Confirma);
  if (ok?.confirmar !== true) {
    return inputRequired({
      inputRequests: {
        confirmar: inputRequired.elicit({ message: `Reservar 1 vaga em "${turma.titulo}" para ${email}?`, requestedSchema: Confirma })
      }
    });
  }
  turma.vagas -= 1;
  return { content: [{ type: 'text', text: `reservado: ${turma_id} para ${email} (restam ${turma.vagas})` }] };
}

// teste-confirmacao.mjs — shows the MRTR (revision 2026-07-28): the reservar_vaga tool
// returns resultType "input_required"; the client asks the user and repeats the call.
// Usage: node teste-confirmacao.mjs sim   (the "user" accepts)
//        node teste-confirmacao.mjs nao   (the "user" declines)
import { Client, StreamableHTTPClientTransport } from '@modelcontextprotocol/client';
import { createMcpHandler } from '@modelcontextprotocol/server';
import { createServer } from './servidor.mjs';

const resposta = process.argv[2] === 'nao' ? 'nao' : 'sim';
const handler = createMcpHandler(createServer);
const ligar = async extra => {
  const c = new Client({ name: 'teste-confirmacao', version: '1.0.0' },
    { versionNegotiation: { mode: 'auto' }, capabilities: { elicitation: { form: {} } }, ...extra });
  await c.connect(new StreamableHTTPClientTransport(new URL('http://teste.local/mcp'),
    { fetch: (url, init) => handler.fetch(new Request(url, init)) }));
  return c;
};
const args = { turma_id: 'html-01', email: 'aluno@exemplo.com' };

// 1st round "by hand": what arrives from the server before the user answers.
const cru = await ligar({ inputRequired: { autoFulfill: false } });
const volta1 = await cru.request({ method: 'tools/call', params: { name: 'reservar_vaga', arguments: args } }, { allowInputRequired: true });
console.log(`1ª volta: resultType=${volta1.resultType} · pede: ${Object.keys(volta1.inputRequests ?? {}).join(', ')}`);
await cru.close();

// Normal flow: the client SDK calls your elicitation handler and repeats the call on its own.
const cliente = await ligar({});
cliente.setRequestHandler('elicitation/create', async req => {
  console.log(`[cliente] pergunta ao usuário: ${req.params.message} → ${resposta}`);
  return resposta === 'sim' ? { action: 'accept', content: { confirmar: true } } : { action: 'decline' };
});
const fim = await cliente.callTool({ name: 'reservar_vaga', arguments: args });
console.log(`resultado: ${fim.content[0].text} · isError=${fim.isError === true}`);
await cliente.close();
await handler.close();
process.exitCode = fim.isError ? 1 : 0;

04 · Common mistake: a client that can't ask

Without capabilities.elicitation, the server has no way to ask for the confirmation.

Terminal · client without the capability
cd ~/projetos/formacao-webmcp-mcp-v72/kit
node teste-sem-capacidade.mjs; echo "saída: $?"
Example from the repository
recusado: -32021 Cannot request input 'confirmar' (elicitation/create): the request's client capabilities do not declare the re
saída: 1

The SDK refuses with -32021 before sending the request. On a real host, this means that client can't use the tool with confirmation: say so in the description or offer another path.

05 · Three things to watch

1. The answer is not trustworthy

inputResponses comes from the client. Validate it with a schema (acceptedContent does this) before acting.

2. Nothing survives between rounds

The server is stateless: the 2nd round is a separate request. A multi-step flow keeps what has already been proven in requestState, signed with createRequestStateCodec (HMAC). It is signed, not encrypted: no secrets inside.

3. Old client

On a 2025 connection, the server SDK converts the input_required into an old-style elicitation/create (shim on by default). The same handler serves both eras.
